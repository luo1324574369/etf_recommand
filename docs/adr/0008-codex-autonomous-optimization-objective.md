# ADR 0008：Codex 自主优化采用风险调整后收益目标

- 状态：提议
- 日期：2026-08-22

本 ADR supersede ADR 0007 中关于“人工批准”和“仅季度发布”的流程约束；ADR 0007 中关于 OOS 证据、沙箱隔离、组合增量贡献和版本回滚的技术原则继续保留。

## 背景

系统计划由 Codex Skill 读取静态回测报告，自动诊断因子和参数，执行候选验证，并决定是否生成新的策略版本。单纯最大化总收益容易把噪声、偶然行情和高换手误判为有效改进。

## 决策

自动优化的主目标采用风险调整后收益，而不是单一总收益。候选方案必须同时评估年化收益、Sharpe、最大回撤、OOS 稳定性、换手率、数据质量和基准超额收益。

候选只有在 OOS 和压力测试中满足预设门槛，且没有明显增加回撤、换手或数据依赖风险时，才允许自动发布。任何单次回测收益创纪录但 OOS 恶化的方案都不得发布。自动发布必须创建新版本、记录完整证据，并保留上一正式版本以便自动回滚。

现有因子允许由 Codex 自动调整组合、参数、方向和权重。新因子代码只能在隔离沙箱中生成和运行；必须在最近24个月窗口内通过前12个月选择期和后12个月最终盲测及压力测试，才可进入正式因子注册表。

自动回滚采用分级规则：数据质量阻断、代码异常、未来函数或硬性最大回撤突破时立即回滚；普通绩效恶化需要连续三个评估窗口低于基准或发布门槛才回滚；单个普通亏损窗口不触发回滚。

每次 Codex 优化运行采用有限预算循环：设置最大迭代轮数、最大运行时间、最大测试次数和最大数据调用量；连续三轮没有风险调整后收益改进时提前停止。停止后必须归档候选比较、淘汰原因、最终版本和回滚点，不允许无限搜索。

自动修改范围限定为因子定义、因子组合、参数和权重。数据源、数据质量门禁、成交模型、风险约束、报告生成器和回测核心不属于自动优化范围；这些部分必须通过独立的工程变更流程修改。

候选评分采用加权评分：OOS 稳定性 30%、Sharpe 25%、年化收益 20%、最大回撤 15%、换手率与交易成本 10%。数据质量、未来函数、最大回撤上限等硬门槛先于加权评分执行，未通过的候选不得排名或发布。

初始硬门槛为：数据质量通过且无未来函数；前12个月选择期和后12个月最终盲测累计超额收益均不低于 0；两期最小 Sharpe 不低于 0.3；最大回撤不超过 35%；年化换手率不超过 360%；相对当前正式版本综合评分至少提升 5%；最大回撤恶化不超过 3 个百分点；通过牛市、熊市、震荡市和高波动压力测试。

自动闭环通过项目 Skill `$etf-autopilot` 启动。Skill 负责读取已有静态报告、执行诊断和候选搜索、运行验证、发布或回滚，并生成本轮决策报告；系统不接入外部 AI，也不依赖系统定时调度。

每次自动发布在独立的 `codex/autopilot/<date>-<run-id>` 分支上创建版本提交并推送远端。正式配置通过版本清单指向通过验证的 commit，不直接覆盖 `main`；回滚通过切换到上一通过版本完成。

正式策略改用独立的版本化配置清单记录当前激活版本、因子组合、参数、权重、约束、证据报告和回滚目标。`config/settings.py` 只保留默认值和代码常量，自动发布不直接修改核心代码。

如果一轮搜索没有候选同时通过全部 OOS、压力测试和硬门槛，保持当前正式版本不变，归档失败原因和诊断报告，不降低门槛、不强行选择未通过候选。

候选通过全部门槛后立即发布，不设置固定冷却期；单轮最多发布一个最佳通过候选。发布仍必须绑定唯一配置哈希和完整证据，以便后续去重、审计和回滚。

相同配置哈希不得重复发布；已自动回滚的版本在没有新数据和新验证证据前不得重新发布。只有配置实质变化且重新通过完整验证的候选，才有资格再次进入发布流程。

自动优化默认覆盖完整 ETF 宇宙，正式回测不受面板当前手动选择列表限制；数据质量、流动性、行业暴露和持仓约束仍然适用于完整宇宙。

时间验证采用滚动 Walk-Forward：训练区间用于调整因子和参数，正式评估固定使用最近24个月，其中前12个月用于选择和排序，后12个月作为不参与候选比较的最终盲测集，并覆盖牛市、熊市、震荡市和高波动阶段。

自动发布仅作用于回测和模拟盘策略，不连接券商、不下真实订单。自动版本变更必须生成信号、净值、质量和回滚报告，实盘交易属于独立权限范围。

数据质量阻断后，Skill 可以自动刷新主数据源和交叉数据源、修复单位转换、字段映射和缓存，再重新执行完整门禁；如果仍然失败则停止本轮。自动修复不得插值或猜测价格、成交量、复权因子、交易日期或成分权重。

数据修复仅允许确定性操作：重新抓取、已批准源切换、单位转换、日期格式统一、字段映射和缓存清理。禁止插值、前值填充、跨 ETF 借值或猜测价格、成交量、复权因子、交易日期和成分权重。

新因子只能使用已通过质量门禁的历史数据和登记字段，禁止访问网络、实时行情、未来数据或未登记数据源；候选代码必须在沙箱中执行并记录源码哈希。

## 后果

- 优化结果可能不是总收益最高，但更重视可持续性和可执行性。
- 报告必须提供多目标指标及淘汰原因，不能只输出一个排名。
- 自动发布减少人工介入，但发布门槛、回滚触发条件和候选代码沙箱必须是确定性的，不能由单次收益排名直接决定。
- 新因子探索速度会变慢，但可以避免实验代码、未来函数和样本内最优结果直接进入正式策略。
- 分级回滚兼顾风险控制和短期噪声，所有触发证据必须写入运行报告和版本日志。
- 有限预算使每次 Skill 执行可复现、可终止，并避免因偶然噪声持续搜索到过拟合方案。
- 限制修改范围可以让收益变化归因于因子和参数，而不是交易引擎或数据口径变化。
- 加权评分避免优化器只追求收益或 Sharpe 单一指标，但硬门槛仍负责拦截不可接受的风险。
