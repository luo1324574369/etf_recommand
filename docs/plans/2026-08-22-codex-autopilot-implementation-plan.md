# `$etf-autopilot` 自主优化实施计划

## 1. 目标

建立一个由 Codex Skill 驱动的自主优化闭环：读取静态报告，发现因子和参数问题，生成候选，执行数据质量校验、滚动 Walk-Forward、OOS、压力测试和综合评分；通过全部门槛的候选自动发布到模拟盘，并在风险触发时自动回滚。

系统不接入外部 AI、不部署模型、不连接券商、不下真实订单，也不依赖系统定时调度。用户只需调用 `$etf-autopilot`，Skill 在一次有限预算运行中完成闭环。

## 2. 已确定规则

- 主目标：风险调整后收益，不追求单一总收益最大化。
- 评分：OOS 稳定性 30%、Sharpe 25%、年化收益 20%、最大回撤 15%、换手率与交易成本 10%。
- 硬门槛：数据质量通过、无未来函数、12/24 个月 OOS 超额不低于 0、OOS Sharpe 不低于 0.3、最大回撤不超过 35%、年化换手率不超过 360%、综合评分较当前版本提升至少 5%、最大回撤恶化不超过 3 个百分点，并通过市场阶段压力测试。
- 优化范围：自动调整现有因子组合、参数、方向和权重；新因子只能在沙箱生成并经过完整 OOS 后发布。
- 数据范围：完整 ETF 宇宙，不依赖面板当前选择列表。
- 时间验证：滚动 Walk-Forward，12 个月 OOS 初筛、24 个月 OOS 确认，最新未参与优化区间作为最终留出测试集。
- 发布：候选通过即发布，无冷却期；单轮最多发布一个候选；同配置哈希不重复发布，被回滚版本在新证据前禁止重发。
- 失败：无候选通过时保持当前版本，归档淘汰原因，不降低门槛。
- 回滚：数据质量/代码异常/未来函数/硬回撤立即回滚；连续 3 个评估窗口低于门槛或基准才因绩效回滚。
- 版本：创建并推送 `codex/autopilot/<date>-<run-id>` 分支，正式配置通过版本清单指向 commit，不直接改 `main`。
- 数据修复：只允许重新抓取、已批准源切换、单位转换、字段映射和缓存清理；禁止插值、前值填充、跨 ETF 借值和猜测数据。

## 3. 目标架构

```text
$etf-autopilot
  -> AutopilotService
  -> 加载 active-config.json 与最近正式报告
  -> 数据质量门禁 / 确定性修复 / 再校验
  -> 基线运行
  -> 候选生成
       ├─ 现有因子组合、参数、权重搜索
       └─ 新因子源码生成 -> FactorSandbox
  -> Walk-Forward / OOS / 留出集 / 压力测试
  -> 硬门槛
  -> 风险调整评分与候选排序
  -> 配置哈希去重与回滚锁定
  -> 发布或保持当前版本
  -> 静态决策报告 + Git 分支/commit
```

## 4. 计划新增或调整

### 4.1 Skill 入口

新增项目 Skill `skills/etf-autopilot/SKILL.md`，只负责指导 Codex：

1. 调用唯一的 Python 编排入口；
2. 阅读 `report-data.json`、运行清单和候选对比；
3. 发现异常时继续执行确定性修复或停止；
4. 不绕过测试、数据门禁和发布门槛；
5. 向用户输出最终版本、收益指标、风险、发布 commit 和回滚点。

### 4.2 自主编排服务

新增 `service/autopilot_service.py`，拆分为以下职责：

- `load_active_version()`：读取当前正式配置和上一版本；
- `repair_and_validate_data()`：执行有限次数的数据刷新和门禁；
- `generate_candidates()`：生成参数、权重、因子组合和沙箱因子候选；
- `evaluate_candidate()`：统一执行回测、OOS、压力测试和暴露检查；
- `score_candidate()`：执行硬门槛和加权评分；
- `publish_candidate()`：写入新版本、配置哈希、证据和回滚目标；
- `rollback_if_needed()`：根据分级规则切回上一通过版本；
- `write_autopilot_report()`：生成机器可读和人类可读静态报告。

### 4.3 版本化配置

新增 `config/strategy_versions/`：

- `active-config.json`：当前正式版本指针；
- `<version>.json`：不可变的因子、参数、权重和约束；
- `release-history.json`：发布、回滚、淘汰和配置哈希记录。

`config/settings.py` 保留默认值和代码常量；正式运行优先读取版本清单，缺失时才使用默认值并在报告中标记。

### 4.4 因子治理

调整 `service/factor_governance_service.py` 和 `strategy/factor_registry.py`：

- 将人工 `approve` 和季度窗口替换为确定性门槛；
- 新因子必须保存源码哈希、沙箱结果、依赖字段、OOS 证据和压力测试证据；
- 通过后自动从候选状态转为 active；
- 回滚后增加回滚锁，直到出现新数据和新证据；
- 保留所有历史版本，禁止覆盖旧定义。

### 4.5 报告

新增 `reports/autopilot/YYYY-MM-DD/<run-id>/`：

- `autopilot-manifest.json`；
- `candidate-comparison.json`；
- `decision.md`；
- `decision.html`；
- `release.json` 或 `rollback.json`；
- 每个候选关联正式回测报告、OOS 区间、压力测试和淘汰原因。

## 5. 有限预算初始值

第一版使用可配置默认值：最大 20 轮迭代、最大 100 次候选回测、最大 30 分钟、最大 200 次数据调用；连续 3 轮综合评分无提升即停止。所有预算消耗写入报告。

## 6. 测试计划

- 配置加载、版本切换、配置哈希去重和回滚锁测试；
- 数据阻断、确定性修复和修复后仍阻断测试；
- 新因子沙箱禁止网络/导入/未来字段测试；
- 12/24 个月 OOS 边界测试；
- 硬门槛逐项淘汰测试；
- 综合评分排序和至少 5% 改进测试；
- 连续 3 个窗口触发绩效回滚测试；
- 无候选通过时保持当前版本测试；
- 自动发布分支、commit、报告和回滚指针测试；
- 完整真实端到端：质量门禁 → 基线 → 候选 → OOS → 发布/回滚 → 静态报告。

## 7. 实施顺序

1. 先建立版本化配置和配置哈希；
2. 抽取统一候选评估器和硬门槛；
3. 接入现有 Walk-Forward、因子健康和 FactorSandbox；
4. 实现自动发布、回滚和报告归档；
5. 编写 `$etf-autopilot` Skill；
6. 用离线固定数据完成端到端测试；
7. 再用真实 ETF 宇宙执行一次受限自主运行；
8. 最后更新 Streamlit，仅展示自动版本、报告、发布和回滚状态。

## 8. 非目标

- 不接入 OpenAI、其他模型 API 或外部 AI 服务；
- 不让候选代码访问网络、生产配置或未登记数据；
- 不自动连接券商或执行真实交易；
- 不自动修改数据源、成交模型、风险约束和回测核心；
- 不以单次历史收益最大化作为发布依据。
